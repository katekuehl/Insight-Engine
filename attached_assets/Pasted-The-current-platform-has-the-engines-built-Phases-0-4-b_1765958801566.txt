# What Users NEVER See
*   ❌ Code or logs
*   ❌ DAG task names
*   ❌ Stack traces or technical errors
*   ❌ Database queries
*   ❌ Model training metrics (internal only)
*   ❌ API response codes
*   ❌ Test results

***

# What Users DO See
*   ✅ Business-friendly stage names
*   ✅ Real-time progress (%)
*   ✅ Estimated time remaining
*   ✅ Business metrics (records validated, insights found, opportunities identified)
*   ✅ Completion checklist with one-liners
*   ✅ Clear error messages with actionable solutions
*   ✅ Next steps (View Results, Export, etc)

# Backend to Frontend Data Flow
**Backend sends progress events:**
```javascript
{
  type: "progress_update",
  analysis_run_id: "run_12345",
  engine: "descriptive_analytics",
  engine_display_name: "Understanding Your Data",
  status: "running",
  progress_percent: 40,
  message: "Processing 2,847 records..."
}

// On completion:
{
  type: "analysis_complete",
  engines_completed: [
    {
      display_name: "Understanding Your Data",
      summary: "2,847 records validated",
      metrics: { records: 2847 }
    },
    // ...
  ],
  total_duration_seconds: 75
}
-----Component Structure
AnalysisProgressTracker
├─ ProgressHeader (title, time, status)
├─ EngineProgressList
│  ├─ EngineProgressItem × N
│  │  ├─ StatusIcon (●/○/✓/✗)
│  │  ├─ EngineName (user-friendly)
│  │  ├─ ProgressBar (if running)
│  │  ├─ StatusMessage (real-time)
│  │  └─ Summary (business metric)
│  └─ EstimatedTime
├─ ErrorStateCard (if failed)
├─ CompletionChecklist (when done)
└─ ActionButtons (View Results, Export)
-----User Journey
User clicks "Run Analysis"
↓
Progress Tracker appears (Running state)
↓
User watches stages complete in sequence
↓
All ✓ Complete
↓
Completion Checklist shown
↓
Click [View Full Results]
↓
Analysis Reports page (full findings, visualizations)
User never sees code, logs, or technical details at any point.
