Here’s how the app should run on the backend:
Backend Execution Flow (Data-First Architecture)
Phase 1: Data Ingestion Pipeline (Runs Daily/On-Demand)

Trigger: Daily at 2 AM OR manual trigger via API

1. GA4_CONNECTOR.sync()
   ├─ Query GA4 API for yesterday's metrics
   ├─ Transform to WebsiteMetricsSchema (22 fields)
   ├─ Validate schema (all 22 fields, no nulls)
   ├─ If valid → INSERT to metricsAnalytics table
   ├─ If invalid → LOG ERROR, STOP, alert user
   └─ Return: {status: SUCCESS/FAILED, records_inserted: N, validation_errors: []}

2. GOOGLE_ADS_CONNECTOR.sync()
   ├─ Query Google Ads API for yesterday's metrics
   ├─ Transform to AdsMetricsSchema with platform: "google_ads"
   ├─ Validate schema (15 fields)
   ├─ If valid → INSERT to metricsAds with platform filter
   ├─ If invalid → LOG ERROR, STOP, alert user
   └─ Return: {status: SUCCESS/FAILED, records_inserted: N}

3. META_ADS_CONNECTOR.sync()
   ├─ Query Meta Ads API for yesterday's metrics
   ├─ Transform to AdsMetricsSchema with platform: "meta_ads"
   ├─ Validate schema (16 fields)
   ├─ If valid → INSERT to metricsAds with platform filter
   ├─ If invalid → LOG ERROR, STOP, alert user
   └─ Return: {status: SUCCESS/FAILED, records_inserted: N}

4. SALESFORCE_CRM_CONNECTOR.sync()
   ├─ Query Salesforce for CRM data (leads, opps, deals, revenue)
   ├─ Transform to CrmMetricsSchema (33 fields)
   ├─ Validate schema + cross-field rules (won+lost+open = total opps)
   ├─ If valid → INSERT to metricsCrm
   ├─ If invalid → LOG ERROR, STOP, alert user
   └─ Return: {status: SUCCESS/FAILED, records_inserted: N}

5. SALESFORCE_PARDOT_CONNECTOR.sync()
   ├─ Query Pardot for email campaign data
   ├─ Transform to EmailMetricsSchema (27 fields)
   ├─ Validate schema (all rates 0-100, etc.)
   ├─ If valid → INSERT to metricsEmail
   ├─ If invalid → LOG ERROR, STOP, alert user
   └─ Return: {status: SUCCESS/FAILED, records_inserted: N}

All 5 connectors run in PARALLEL (async tasks)

Output: Aggregated sync report
{
  "ga4": {status: "SUCCESS", records: 1},

Phase 2: Data Verification (Runs After Ingestion)
Trigger: Automatically after all connectors complete

1. RUN_DATA_QUALITY_CHECKS()
   ├─ Query each metrics table
   ├─ Check: Row count = 12 (for 12 months of historical data)
   ├─ Check: No NULL values in required columns
   ├─ Check: All numeric validation rules pass
   ├─ Check: No synthetic records (is_synthetic = FALSE)
   ├─ Check: Date range = Jan 1, 2025 to Dec 31, 2025
   └─ Return: {quality_score: 0-100%, passed: bool, issues: []}

If quality_score < 95%:
  → STOP analysis pipeline
  → Alert: "Data quality issues detected. Resolve before proceeding."
  → Return: {status: "DATA_QUALITY_FAILED", reason: [...]}

If quality_score >= 95%:
  → Continue to Phase 3

CSV Import vs API Connectors - Same Treatment
“Here’s how to handle our current situation:
Right now:
	•	We don’t have live API credentials for GA4, Google Ads, Meta Ads, Salesforce, or Pardot
	•	Instead, I’ve uploaded 5 CSVs with 2025 data (one per source)
	•	This is temporary for testing/development
But here’s the critical part:
The CSVs should be treated EXACTLY like API data. Same validation, same schema, same insertion logic. The only difference is the source:

API Path: 
  GA4_Connector → Query GA4 API → Normalize → Validate → Insert

CSV Path (temporarily):
  CSV File → Read CSV → Normalize → Validate → Insert

RESULT: Same data in database. Same quality checks. Same engine behavior.

What this means for code architecture:
	1.	Create a DataSource abstraction layer
class DataSource:
    def fetch(self):
        """Return raw data. Implementation varies."""
        pass

class GA4DataSource(DataSource):
    def fetch(self):
        # Query GA4 API
        return ga4_client.query(...)

class CSVDataSource(DataSource):
    def fetch(self):
        # Read CSV file
        return pd.read_csv('website_performance_2025.csv')

# Usage is identical:
source = GA4DataSource() if USE_API else CSVDataSource()
raw_data = source.fetch()  # Same interface, different implementation
normalized = normalize_to_schema(raw_data)
validate_schema(normalized)
insert_to_database(normalized)

2.	The normalization/validation/insertion pipeline is IDENTICAL
Whether data comes from API or CSV, it flows through:

Raw Data (API or CSV) 
  → Normalize to WebsiteMetricsSchema
  → Validate (all 22 fields, types, ranges)
  → Insert to metricsAnalytics table
  → Log: "Successfully imported GA4 data"

3.	No special handling for CSV
Don’t do this:
❌ WRONG - Different treatment for CSV
if source == "CSV":
    data = read_csv()
    # Skip validation? Use defaults? Fill gaps?
    insert_anyway()

Do this:

✅ CORRECT - Same treatment for both
if source == "CSV":
    data = read_csv()
    normalize_to_schema(data)
    validate_schema(data)  # Same validation as API
    insert_to_database(data)  # Same insertion as API
